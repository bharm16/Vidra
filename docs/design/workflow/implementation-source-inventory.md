The workflow documents are uncommitted design work above that baseline; they do not describe shipped behavior. This inventory covers all **22 state groups** in [state-model.json](state-model.json), against [workflow-state-contract.md](workflow-state-contract.md) and its **137 acceptance cases / 22 model traces** at inspection time. It supplements the [earlier behavior inventory](../2026-10-09-history-state-inventory.md).

Source paths and test assertions were inspected; tests were not executed for this inventory. Existing tests below are useful starting evidence and harnesses, not proof of the new contract. Absence claims refer to the active source owners, route map, and tests searched here. No provider calls, production changes or migrations were performed.

## What the dispositions mean

- **KEEP:** Preserve a working boundary/invariant and its applicable tests.
- **EXTEND:** Keep that owner and add the new contract through it; do not create a rival source of truth.
- **REPLACE:** Existing behavior directly conflicts with the new contract. Preserve readable records and useful lower-level services while replacing that behavior and its contradictory assertions.
- **NEW:** No active implementation supplies the required behavior. Related names, historical fields or generic infrastructure do not count as an implementation.

## Dependencies that determine the build order

1. **Identity and schemas precede orchestration.** Project adapters, conversation IDs, execution drafts versus contextual targets, immutable requests, stable slots and media-version references must be decided before replacing UI state. Existing session and Studio IDs remain readable; no title/prompt-based merging. Shared schemas are the contract boundary, and the root guide requires typechecking immediately after a shared-contract change. See [session schema](../../../shared/schemas/session.schemas.ts), [Studio submission schema](../../../shared/schemas/studio.schemas.ts) and [engineering rules](../../../CLAUDE.md).
2. **Durable drafts precede concurrent follow-ups.** The present client deliberately pauses autosave during generation. Enabling free navigation/multiple editable requests before a separate draft store and revision/conflict protocol would retain that data-loss risk. Keep text editing/undo behavior while replacing persistence ownership.
3. **One submission authority precedes all executors.** [RequestIdempotencyService](../../../server/src/services/admission/idempotency/RequestIdempotencyService.ts) already owns transactional payload-hash claims and response receipts. [VideoJobStore.createJobWithReceipt](../../../server/src/services/video-generation/runtime/VideoJobStore.ts#L123) publishes a queued video job with its receipt atomically. Extend this authority for execution-draft revision uniqueness and operation envelopes; do not introduce parallel acceptance ledgers for Studio, export and uploads. Current default pending-lock/replay lifetimes are six minutes/24 hours; explicitly adapt retention and unknown-outcome handling to J01/J13/J15.
4. **Provider attempt records precede truthful cancellation/recovery.** [StudioImageRunner](../../../server/src/services/studio/providers/types.ts) exposes one `run()` promise; [VideoProvider](../../../server/src/services/video-generation/providers/types.ts) exposes one `generate()` promise. Neither port provides durable start/status/cancel operations. [VideoJobRecord](../../../server/src/services/video-generation/runtime/types.ts) has no external provider-operation identity. Keep clients, model input shaping and storage, but add durable attempt handles/evidence before claiming restart-safe J04/J05/J10 behavior.
5. **Preserve the actual worker, replace its retry decisions.** [VideoJobWorker](../../../server/src/services/video-generation/runtime/VideoJobWorker.ts), [processVideoJob](../../../server/src/services/video-generation/runtime/processVideoJob.ts), [inlineProcessor](../../../server/src/routes/preview/inlineProcessor.ts) and their [registration](../../../server/src/config/services/video-generation.services.ts) are active implementation seams, with startup controlled in [services.initialize](../../../server/src/config/services.initialize.ts#L321). Current retryability classification/requeue and Studio stale-turn termination do not prove provider nonacceptance. Their new policy must consume attempt evidence rather than merely rename states.
6. **Media ownership precedes new destinations.** Keep owned media, signed-URL minting, admission fingerprints, owed attachment records and exact take identity. Add project/recovery-inbox association through those owners. Current admission requires a session and words version; remove that product prerequisite through an explicit destination adapter, while retaining legacy session attachment. Do not bypass admission with a new generic project upload writer.
7. **Finishing video is NEW work.** Saved generation history and historical continuity fields are not a composition document, timeline editor or exporter. Build the edit schema/revisions/validation, then its renderer/export executor, then the UI. Reuse ownership/storage and the new request protocol, not the old words-version timeline as an editing engine.
8. **Customer billing is NEW; provider budgets and old refunds stay separate.** [Free intake](../../../server/src/routes/preview/handlers/video-generate/intake.ts#L145) reserves zero credits, and the atomic job method rejects nonzero reservations. [StudioSpendLedger](../../../server/src/services/studio/StudioSpendLedger.ts) and [SketchBudgetService](../../../server/src/services/sketch-budget/SketchBudgetService.ts) enforce provider-spend allowances. [LegacyCreditRefundService](../../../server/src/services/video-generation/refunds/LegacyCreditRefundService.ts) only preserves refunds for earlier charged jobs. None supplies quotes, customer entitlements, per-slot paid settlement or P01–P05. The comment in [session.services](../../../server/src/config/services/session.services.ts) mentioning `payment.services.ts` is stale; that file is absent.
