# Interaction contract for the reviewed designs

The October 14 approved removal supersedes earlier presentation requirements for the 39 retired screens. Do not rebuild draft comparison/management/discard screens, context or coupled-setting approval gates, technical attachment/storage/renderer repair screens, billing/checkout/credit receipts, extra retry confirmation, or the retired result notices. Unfinished work is reached through conversation history. Retry is a direct deliberate action with a new execution identity; uncertain acceptance still reconciles the original identity. Data retention, conflict detection, media ownership, idempotency and internal recovery remain required. The retirement record, not older screenshots or state-model labels, determines active UI scope. See the [removal record](../screen-removal-execution-2026-10-14.json).

2026-10-10. Proposed behavior for implementation. Figma contains fixed examples, not live account, provider, storage, clipboard or rendering integrations. This document closes interaction details that cannot be proved by counting frames. The workflow state contract remains authoritative for ownership, accepted work, history and recovery.

## How to interpret the screens

A screen is a rendering of state and current data. Asset names, times, email addresses, request counts and account names are examples, not constants to copy into the application. A shared dialog uses the caller's exact project, draft, source version, export and return destination. Do not navigate to the sample asset merely because a prototype link demonstrates the same operation. Public and private views use different authorization contracts.

State combinations compose: offline + running request + local draft, for example, uses the connectivity, request and draft presentations together. The 126 workflow states and their guarded transitions remain covered by `../workflow/ui-state-evidence.json`; this review adds the public/account states and missing interaction results. It does not require a separate screen for every data value or Cartesian combination.

## Public site, documentation and responsive behavior

- Product links and calls to action retain a safe intended destination through authentication. Authentication does not execute that intent. A video-editor first visit has no invented existing media. A guest draft remains unsubmitted after adoption.
- Public navigation is account-aware. A signed-in creator sees Open workspace and Account; guests see the sign-in/signup actions. Capability links still retain the requested starting action. Pricing questions allow one open answer at a time; selecting another question closes the previous answer, and selecting the open question collapses it.
- Docs contents links scroll the current article to the named section, update focus to its heading, and preserve the search/query context. Search opens over its caller; closing restores it. Error and empty search retain the query. Browser back restores the previous article and scroll position.
- Public shares resolve a grant for one immutable target. Loading, unavailable/revoked, network failure, image, playable video and download failure are distinct. An unavailable link does not reveal private project names, prompts, source history, account data or sibling assets. Use the original link on retry.
- Desktop examples use 1440-pixel canvases; phone examples use 390 pixels. These are reference sizes. At widths below 768 use the single-pane/sheet layouts; 768–1199 uses the same navigation with collapsible side panels; 1200 and wider may show the full desktop workspace. Media stays bounded by available width, and timeline scrolling is intentional.
- Support a 320-pixel viewport and 200% text zoom. Do not shrink body text to force a desktop layout onto a phone. Wrap action rows when needed. Forms and reading content scroll vertically; keep focused inputs and their errors visible when the keyboard opens.
- Dialogs/sheets have a maximum height of the visual viewport minus safe-area insets and 16 pixels on each edge. Their body scrolls; close and primary actions remain reachable. The Figma presentation uses fixed reference canvases, so its editor's zoom setting is not evidence of runtime responsiveness.
- Interactive touch targets are at least 44 by 44 pixels; icon glyphs may be smaller. Use visible focus treatment, semantic labels, labelled errors and polite progress announcements. Do not rely on colour alone. Reduced motion removes nonessential transitions; no preview starts audio automatically.
- Pricing remains bounded free testing under ADR-0023. The revised billing paragraph in the proposed Terms reflects that product state. Policy publication and commercial activation remain separate approval/acceptance work; the design is not a new paid offer.
