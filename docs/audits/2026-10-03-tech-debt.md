## Findings

### 1. Secrets gap: deploy has never run, nightlies are blind

Workflows reference 31 secrets. Six are set (`GROQ_API_KEY`, `OPENAI_API_KEY`, four PostHog values). Missing:

```
ALLOWED_ORIGINS CLOUD_RUN_SERVICE FAL_KEY FIREBASE_SERVICE_ACCOUNT_JSON
FIREBASE_STORAGE_BUCKET FIREBASE_TOKEN FRONTEND_URL GCP_ARTIFACT_REPO
GCP_PROJECT_ID GCP_REGION GCP_SA_KEY GCS_BUCKET_NAME GEMINI_API_KEY
IMAGE_STORAGE_BUCKET REPLICATE_API_TOKEN SPAN_LABELING_MODELS_GCS_URI
VIDEO_STORAGE_BUCKET VITE_ANTHROPIC_API_KEY VITE_FIREBASE_*  (7 values)
```

Consequences, each verified from `gh run list`:

- `deploy-cloudrun-firebase.yml` has zero runs. There is no release path.
- `golden-path.yml`, `live-provider-smoke.yml`, `span-labeling-eval.yml` fail every night (10-01, 10-02, 10-03). Golden path dies at "Run the golden-path spec"; span eval dies at "Fail job on regression", which is the baseline gate, not a secrets failure, and needs an eval-owner decision (re-bless vs investigate).
- `synthetic-harness.yml` has never run. `quality-judge.yml` stopped after 2026-08-27. `performance.yml` last failed 2026-08-27.

**Why it matters:** CLAUDE.md says the replay gate cannot tell you a provider is up and delegates that to the nightly smoke. The smoke has been red or absent for the whole period. The product's only live-provider signal is a developer's laptop.

**Fix:** owner enters the 25 secrets (the GCP values need a service-account key with Cloud Run + Artifact Registry roles). Then re-run deploy and the three nightlies by hand and triage whatever is left. Separately decide the span-eval baseline.

### 5. Frozen stacks still run

ADR-0002 froze continuity, convergence, payment, and credits. On this checkout they still:

- Register in DI and start at boot: `creditRefundSweeper`, `creditReconciliationWorker`, `videoAssetRetentionService`, `videoJobSweeper`, plus the webhook-reconciliation and billing-profile-repair workers, all with killswitch defaults of `true`.
- Mount `/api/payment` behind `apiAuthMiddleware` and a starter-credits middleware, in a product that ADR-0023 says is free.
- Weigh ~19k server lines (continuity 3.9k, convergence 2.1k, payment 1.8k, credits 1.8k, video-generation jobs 9.7k) plus ~4.7k client lines (convergence 2.9k, sequence-editor 0.9k, continuity 0.5k, billing 0.5k). Roughly one server line in six belongs to a frozen stack.

The August audits deliberately kept this code as a revival ledger, so deletion is not proposed. The debt is that the runtime footprint does not match the ADR: every boot, every integration test, and every DI-container test pays for workers that have no customer. The CLAUDE.md rule "do not treat the frozen stacks as load-bearing" is contradicted by the process that starts them.

**Fix (owner decision):** flip the killswitch defaults for the frozen workers to `false` and gate `/api/payment` on a flag that defaults off, with an integration test asserting the api role starts no frozen worker. This is a default change behind existing flags, not a disable-as-stopgap: the flags were built for exactly this. The alternative is to leave it and accept the boot cost until ADR-0002 is revisited.

### 6. Response envelope drift

`server/src/middleware/respond.ts` exports `ok`/`fail` and builds the canonical `ApiSuccessResponse` with `requestId`. Only 2 of 22 route files use it; 13 hand-roll `res.json({ success: true, ... })`. The OpenAPI spec promises the canonical shape. Hand-rolled responses omit `requestId`, and error bodies can drift from `ApiErrorCode`.

**Fix:** mechanical migration of 13 files, one commit, covered by the existing route tests. A lint rule banning `json({ success:` in `server/src/routes/` keeps it fixed.
